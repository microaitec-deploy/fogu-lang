Official documentation

The Fogu language

Fogu (.fg files) is a small, predictable scripting language, dynamically typed with optional type annotations, built for automation, infrastructure, systems integration and small services. The reference implementation is written in Rust and ships an interpreter, a JIT compiler (Cranelift), a REPL, a CLI, a package manager and standalone executables.

Simple

A small grammar, optional semicolons, no implicit coercions.

Predictable

Errors are values, lexical scope, no hoisting, names and types checked before running.

Practical

HTTP, TCP/UDP, SQL, key-value, cron and events in the standard library.

Installation

Requires Rust (2024 edition) and git on the PATH (for packages).

First steps

Variables and types

let creates a mutable variable; const an immutable binding (the referenced object may still change). Scope is lexical, each { } block creates a new scope and there is no hoisting. Declaring the same name twice in the same scope is an error.

Conversions and truthiness

  • There are no implicit coercions: "10" + 2 is an error. Use int("10"), float(10), str(10).
  • The only automatic promotion is int → float in arithmetic: 1 + 2.5 == 3.5.
  • Only false and nil are falsy; 0, "", [] and {} are truthy.
  • == compares lists and maps by structure; structs by identity (or with their equals method).

Type annotations

Annotations are optional. They are checked at runtime (parameters on entry, return values on exit, let/const on assignment) and unknown type names are rejected before the program runs. Annotated numeric functions are still compiled by the JIT.

Built-in type names: int float str bool nil duration list map tuple fn chan error any, plus struct and interface names. error also accepts nil. Generic arguments such as list<int> document the intent; only the outer kind is checked.

Strings and template strings

Template strings use backticks and interpolate any expression with ${...}. They may span several lines.

str methods: split upper lower trim replace starts_with ends_with repeat lines chars slice.

Durations

Literals with a unit (ns us ms s m h d, decimals allowed) create duration values, stored in nanoseconds. They are accepted by time.delay, time.sleep, cron.every and timeout.

Fields: ns, us, ms (int) and seconds, minutes, hours (float).

Control flow

No parentheses around conditions. match is an expression, with literal patterns, | alternatives, bindings with guards and the _ wildcard. A match must be exhaustive: without a _ (or plain name) arm it is rejected before the program runs.

Functions

Functions are first-class values with closures. There are three forms: declaration, anonymous function and arrow function. Parameters may have default values (which may use earlier parameters) and the last one may be variadic. Functions and structs may be generic; type parameters are erased at runtime.

Missing arguments are nil (or their default value); passing too many is an error, except for variadic functions.

Lists and maps

  • Lists: push pop shift unshift insert remove first last contains index_of join reverse slice concat sort map filter each find any all reduce
  • Maps: keys values entries has get set remove merge
  • All of them work as methods (xs.push(1)) or as functions (push(xs, 1)).

Errors as values

There is no try/catch. A function returns value, error; the ? operator returns the error to the caller. An error has message, cause and trace. ? may only be used in functions whose declared return type includes error (or that are not annotated).

The operational errors of native functions (a file that does not open, a refused connection, invalid SQL or JSON) are error values too. Programming errors (for example, an argument of the wrong type) stop the program.

Note: const [a, b] = f() destructures lists. If a native function returns a list (for example json.parse("[1, 2]") or db.query(...)), use ? instead of destructuring.

panic("msg") signals an unrecoverable failure. In an fg task it does not stop the other tasks, unless the program runs with --strict.

Structs, interfaces and composition

There is no inheritance: reuse comes from embed. The constructor is called new and methods reach the instance through this. Structs compare by identity, unless they define equals. Interfaces are structural: any struct (or map of functions) with the required methods satisfies them, without declaring it.

Modules and visibility

Each file is a module, evaluated only once. Use export to export functions, let/const, structs and interfaces. Names starting with _ are private to the module: they cannot be imported, read through module._x, or used as fields or methods of a struct outside the module where it was declared.

Concurrency: fg, chan, select

fg starts a cooperative task (not an OS thread). Buffered or unbuffered channels connect tasks; select waits for the first ready case (choosing randomly among ready ones) and timeout(d) returns a channel that receives a value after d. The runtime detects deadlocks.

Conventions

Errors are values. Operational failures — a missing file, a refused connection, a server error, malformed input — come back as an error value: handle them with ? (propagate) or const [value, err] = f(). Programming mistakes — a wrong argument type, an unknown option — stop the program with a message. Options are passed as a last map argument: f(x, { timeout: 5s }). Durations accept a duration literal (500ms, 2s, 1h) or an int number of milliseconds. Network operations wait cooperatively: other fg tasks keep running while one waits.

Testing

Tests live in *.test.fg files and use fogu:test. fogu test finds them (under the current folder, or the given files and folders), runs each file in a fresh interpreter and exits with 1 if a test fails. A test fails when an expectation fails, when it raises an error, or when it returns an error value — so ? can be used inside tests.

Matchers: toBe, toEqual, toBeTruthy, toBeFalsy, toBeNil, toBeError, toBeType("int"), toContain, toHaveLength, toBeGreaterThan, toBeLessThan, toBeCloseTo(x, eps?) — each can be negated with .not.

Packages

Packages come from git repositories, .tar.gz archives or local folders and live in a global store (~/.fogu/fogu_modules/<name>@<commit>). fogu.lock pins the commit and the sha256 checksum; install scripts are never run.

Standalone executables

fogu build --compile produces dist/<name> (.exe on Windows): a copy of the Fogu runtime with the program appended — the entry file, every module it imports and the packages it uses. The executable runs on machines without Fogu and passes every command-line argument to the program.

Files the program reads at runtime (a React build, templates, images…) are embedded with "embed": ["dist", "templates/*.html"] in fogu.json or --embed <glob>. The program finds them with Fogu.asset(path), which works the same when running from the sources:

On first run the bundle is extracted to <temp>/fogu-bundles/<hash>; --target wasm is not supported yet.

JIT compiler

The interpreter is the semantic reference. The JIT (Cranelift) compiles hot numeric functions and loops (int/float/bool, if, while, for a..b, match, math.*, numeric type annotations); when something is not supported, the code keeps running in the interpreter, with the same results and error messages.

Status and roadmap

The language is in development (before 1.0 there may be incompatible changes). It does not have yet: permissions --allow-*, fogu audit, fogu publish, static type inference, or the bytecode VM. The detailed status of every feature is in CHECKLIST.md and the full specification in docs/spec.md.

The standard library reference on this page is generated by docs/tools/gen_reference.py, which runs the examples to show their real output.
